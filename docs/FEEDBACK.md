# Product feedback and friction log

The submission needs feedback on every tool; friction logs can add up to 10% to the judging score.

## Per-tool feedback
| Tool | Used for | Worked well | Needs work | Onboarding | Build again? |
|---|---|---|---|---|---|
| MCP Python SDK (`mcp` 2.3) | The Encore MCP server over Streamable HTTP; the web simulator's MCP client | Server ran on spec 2025-11-25 with no config; the in-process `Client(server)` made integration tests easy | Most tutorials still use v1 `FastMCP` (v2 renamed it `MCPServer`); `-> dict` tools get no `structured_content`; client errors arrive wrapped in an `ExceptionGroup` (see friction log) | Under an hour from `pip install mcp` to a working tool, once we found the v2 names | Yes. Small API, and the same server worked unchanged in Claude Code |
| MCP Apps (Python SDK Apps extension + `@modelcontextprotocol/ext-apps`) | Interactive `ui://encore/flashcards.html` view for `view_flashcards` | The Python extension binds the UI resource and advertises it on the tool; the browser SDK handles host messaging | The UI must be bundled into one self-contained HTML file; a plain browser can't render it, so it needs a compatible host to try | A build step (`npm run build:mcp-app`) plus reading the ext-apps examples | Yes. The text fallback plus interactive view pattern is a good fit for voice |
| Alexa+ docs, MCP spec, hackathon FAQ | Choosing the self-hosted MCP + simulated Alexa+ path | The FAQ clearly confirmed a web page acting as a real MCP client is accepted; the Streamable HTTP spec page was precise | The add-on setup pages don't all say the Alexa+ tooling (Category SDK, MCP Toolkit, Web Simulator) is partner-only; the FAQ notes this confused people | Fast once we read the FAQ | Yes, and we would connect to a real Alexa+ device if that opens up |
| Amazon Bedrock (boto3 Converse) | Planned for card generation and the agent; the code path exists (`LLM_PROVIDER=bedrock`) with mocked tests | `list_foundation_models` and `get_foundation_model_availability` worked and showed the real state | Our new account could never call a model (see friction log): `Operation not allowed` in some regions, `being verified` in others, and no explanation in the console. Model IDs were hard to find | Never reached a first successful call in 4+ days, so we dropped it and its mini challenge | Yes, once the account works. The Converse API itself looks clean |
| Gemini API (REST, `gemini-3.1-flash-lite`) | Card generation and the agent loop, via a 50-line stdlib client (`gemini.py`) | Free key in a minute, no card; function calling with `parametersJsonSchema` accepted MCP tool schemas as-is | Free tier often returned 503 "high demand" and 429 quota errors; replies took 17-107 s until we set minimal thinking | Fast: one REST call worked first try | Yes, for prototypes |
| Web Speech API (browser) | Speech-to-text for answers, text-to-speech for Encore's replies | Zero setup in Chrome and Edge | Not available in every browser; `speechSynthesis.cancel()` fires `onerror("interrupted")`, which looks like a failure | Immediate | Yes, with a typed fallback |

## Friction log
| Date | Task | Steps | Expected | Actual | Severity | Workaround | Suggestion |
|---|---|---|---|---|---|---|---|
| 2026-10-11 | Start an MCP server | `pip install mcp`, then `from mcp.server.fastmcp import FastMCP` | Works as in most tutorials | `ModuleNotFoundError`: v2 renamed FastMCP to MCPServer | Low | `from mcp.server.mcpserver import MCPServer` | Keep a compatibility alias, or update the getting-started examples |
| 2026-10-12 | Find supported Bedrock model IDs | Expect model IDs listed in the Bedrock console | Visible list in console | Had to search docs separately; `amazon.nova-lite-v1:0` not shown in all regions | Medium | Check AWS docs / blog posts for current IDs | Add a "copy model ID" button or a filterable table in the console |
| 2026-10-12 | Parse Bedrock Converse response for text | `response["output"]["message"]["content"][0]["text"]` | Shorter path | Nested structure requires multiple dict accesses; easy to typo | Low | Helper function `_call_bedrock()` wraps the path | Consider a typed SDK response object |
| 2026-10-12 | Read a tool's structured result over MCP | Tool annotated `-> dict`; client reads `result.structured_content` | Structured data, like `-> str` tools get (`{"result": ...}`) | `structured_content` is `None` for `-> dict`; only JSON text in `content[0].text` | Low | Parse the JSON text (`json.loads`) | Infer an object schema for `dict` returns, or document the difference |
| 2026-10-13 | First Bedrock call from a new AWS account | Valid root keys, `converse` on Nova Lite / Micro / Claude Haiku in us-east-1, us-west-2, ap-south-1, us-east-2, eu-west-1 | A model reply, or a clear "not enabled" message | `ValidationException: Operation not allowed` in three regions; `AccessDeniedException: Your account is currently being verified` in two; `get_foundation_model_availability` said `NOT_AUTHORIZED`; nothing in the console explained it. Still blocked 4 days later | High (we dropped Bedrock and the AWS Builder challenge) | Switched the model to Gemini behind a provider flag | Return the "being verified" reason in every region, show account authorization status on the Bedrock console, and state any Free plan limits up front |
| 2026-10-13 | Call Gemini from the agent loop | `gemini-flash-latest`, free tier | Replies in a few seconds | 503 "high demand", then 429 quota; the working models took 17-107 s per reply | Medium | Retry 503s, use `gemini-3.1-flash-lite` with `thinkingLevel: minimal`, show "this can take up to half a minute" | Publish free-tier latency expectations next to the rate limits |
| 2026-10-13 | Handle "MCP server is down" in the web client | Stop `server.py`, send a chat message | A connection error we can catch (e.g. `OSError`) | `httpx.ConnectError` wrapped in an `ExceptionGroup` from the client's task group, so our handler missed it and the page got a plain-text 500 | Medium | Unwrap single-exception groups; catch all errors and return JSON | Raise one typed connection error from `streamable_http_client` |
| 2026-10-17 | Stop speech when the user sends a new message | `speechSynthesis.cancel()` while a reply is being spoken | Silent stop | The utterance's `onerror` fires with `interrupted` after `cancel()` returns, which our UI showed as "Voice output unavailable" | Low | Ignore `interrupted` / `canceled` events | Fire `onend` (not `onerror`) for an intentional cancel, or document it prominently |

## Feature requests
| Request | Why it matters | Priority |
|---|---|---|
| Let developers connect a self-hosted MCP server to a real Alexa+ device or developer console (even a sandbox) | Every Alexa+ track entry has to be shown in a simulator; testing on the real assistant would show real voice behavior | Critical |
| Show Bedrock account authorization status (and any Free plan limits) in the Bedrock console | A new account failed for days with no explanation; one status line would have saved the time | Important |
| A `FastMCP` compatibility alias or a v1-to-v2 migration page in the MCP Python SDK docs | Most examples online still use v1 names | Nice-to-have |
